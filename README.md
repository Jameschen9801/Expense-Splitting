# 分帳即時通

使用 React、Vite 與 Firebase Realtime Database 製作的多人分帳工具。

## 手機記帳與同步

- 新增、編輯、刪除會先寫入此裝置的待同步清單，再依群組順序上傳。重開 App、恢復連線或回到前景時會自動補傳；雲端更新會與尚未上傳的操作合併。
- 未完成的費用／轉帳草稿依群組及使用者保存在此裝置，重新開啟記帳視窗可繼續填寫。保存記錄後會清除草稿。
- 同步狀態顯示離線、待同步筆數、同步中或已同步。裝置上的草稿與待同步清單不是跨裝置備份；清除網站資料也會清除它們。
- 手機彈窗跟隨可見畫面高度，標題與儲存列固定，中間表單獨立捲動。明細先顯示最近 50 筆，可載入更多，搜尋涵蓋全部記錄。
- 手機新增／編輯記錄時，直接在原欄位輸入，鍵盤上方提供下一欄與完成按鈕；完成輸入後使用原本的儲存按鈕。新增費用預設餐飲，分類含旅遊共十一項；舊帳目分類保持相容。常用範本操作已移除。

## 個人與共用帳本

- 首頁選「新增帳本」，可建立個人帳本或共用帳本，預設為適合日常支出的個人帳本。既有帳本仍以共用帳本運作。
- 個人帳本自動由自己付款並記為自己的支出，隱藏付款人、分攤、還款轉帳與成員管理。預設顯示本月明細和支出總額，可查看分類與月份統計；重新開啟 App 會回到上次使用的帳本。
- 個人帳本在資料庫只允許建立者的裝置身分讀寫，不提供邀請碼加入，也不能在建立後直接變更帳本類型。共用帳本保留六位邀請碼、共同記帳與分攤結算。
- 個人帳本目前使用既有匿名裝置身分，請勿清除網站資料並定期匯出 JSON 備份。備份不包含登入憑證；更換裝置或瀏覽器時，雲端存取仍需管理者協助驗證。銀行捷徑也應在建立帳本的同一個 Safari 設定。
- 個人帳本首頁有「銀行自動記帳設定」，帳本設定也有「銀行與卡片設定」直接入口，可在既有帳本設定銀行、卡號末 4 或 5 碼與分類。
- 個人帳本可在帳本設定按「刪除個人帳本」。第二個視窗會顯示帳本名稱與記錄數，需輸入「刪除」才能確認；需要連線並完成待同步資料。確認後刪除雲端帳本及本機帳目、草稿、該帳本銀行規則，其他帳本與裝置登入身分保留。伺服器只留下不可修改的裝置 UID／刪除時間標記，防止舊同步或備份重建原帳本；本機不提供復原操作。

## iOS 銀行通知捷徑

1. 在捷徑會開啟的同一個 Safari 開啟既有個人帳本，點首頁「銀行自動記帳設定」，或從「帳本／群組設定 → 銀行與卡片設定」進入。沒有帳本時才需要新增。主畫面 App 與 Safari 可能使用不同裝置身分，不要清除原 App 資料。
2. 在 App 填寫銀行關鍵字、卡號末 4 或 5 碼與分類，位數須與通知一致，儲存銀行規則。個人帳本會自動記為自己的全額支出；共用帳本才顯示付款人與分攤對象。首次直接展開表單，預設「先確認再新增」；通知測試不會新增帳目。
3. 按「加入銀行通知捷徑」，由 [Apple iCloud 安裝頁](https://www.icloud.com/shortcuts/1e2ff51948f94e508a80098f7367b2f7)加入新版，再回 App 按「已加入，完成綁定」。App 會透過 Apple 的 `shortcuts://run-shortcut` 自動傳入這個瀏覽器的記帳連結，不用重填銀行、卡號或複製連結；Apple 的安裝確認仍須由使用者操作。捷徑將連結存入 iCloud Drive 的 `Shortcuts/ExpenseSplitting-bank-link.txt`，不把銀行、卡號、帳目或登入憑證放入公開範本。之後新增卡片、改分類或停用規則，都只需在 App 儲存；同一個捷徑會選擇唯一符合銀行與末四碼的啟用規則，規則重疊時停止入帳。
4. 在 iOS 27「捷徑 → 自動化 → 通知」選銀行 App 及消費通知篩選條件，將通知標題、副標題、訊息合併成文字，再用「執行捷徑」傳給「銀行通知記帳」。文字須包含銀行名稱、對應的卡號末碼及新臺幣金額。參考 [Apple 的 iOS 27 通知觸發器說明](https://support.apple.com/en-ng/guide/shortcuts/apd932ff833f/10.0/ios/27)。

捷徑會開啟網站後記帳，鎖屏時可能需要解鎖。網站不會在背景監聽其他 App，也不會付款或轉帳。只有測試通知成功且勾選同意後才能啟用自動新增；超過上限、缺少當日日期及疑似重複的通知會先確認。退款、驗證碼、帳單、外幣與無法明確辨識的金額不會自動新增。

通知文字放在網址片段，啟動時即移除；不放進 HTTP 查詢參數、不保存原始通知。規則、私人 HMAC 金鑰與瀏覽器捷徑識別碼只存此瀏覽器，不包含在一般備份。捷徑儲存的連結只允許本網站與固定格式，不能指向其他服務；未綁定或手動執行時會開啟 App 設定，不建立支出。既有每張卡一條連結的舊捷徑仍可使用，手動前綴放在「舊版捷徑手動設定」。支出透過既有身分權限與離線待同步清單保存；相同通知用固定 ID 防止重送重複。本機另保留最近 500 筆通知識別碼；已刪除且超出保留範圍的舊通知不保證去重。確為另一筆相同消費時請手動新增。

捷徑原始內容在 `scripts/ios-bank-shortcut.json`，使用 macOS 內建工具產生可匯入的簽署檔：

```bash
plutil -convert xml1 scripts/ios-bank-shortcut.json -o /tmp/expense-bank-notification-unsigned.shortcut
shortcuts sign --mode anyone --input /tmp/expense-bank-notification-unsigned.shortcut --output 'public/shortcuts/銀行通知記帳.shortcut'
```

iPhone 安裝入口使用 iCloud 分享頁，不直接導向原始二進位檔，避免主畫面 App 將 AEA1 簽署內容顯示成亂碼。無法開啟安裝頁時，可用「下載 ZIP 備用檔」，在「檔案」解壓後開啟 `.shortcut`。ZIP 僅包含簽署的通用捷徑，不含私人資料。更新捷徑時請同步重新產生 `public/shortcuts/bank-notification-shortcut.zip`，並檢查 iCloud 分享版本是否需更新。

## 🚀 快速開始

### 1. 安裝套件
確保你已經安裝 Node.js，然後執行：
```bash
npm install
```

### 2. 啟動開發環境
啟動開發伺服器：
```bash
npm run dev
```

### 3. 執行檢查
```bash
npm run lint
npm run test:logic
npm run build
```

### 4. 建置與部署
本專案已設定 GitHub Actions。當程式碼推送到 `main` 分支時，會自動觸發 `.github/workflows/deploy.yml` 腳本，將 `dist` 的靜態網頁內容自動部署至 GitHub Pages。
- 請確認 GitHub Repository 的 **Settings -> Pages** 中的 **Source** 已設定為 **GitHub Actions**。

### 5. Git 忽略檔案設定
本專案透過 `.gitignore` 已排除：
- `node_modules/`: 第三方依賴套件
- `dist/`, `build/`: 編譯後的輸出檔案
- `.env*`: 敏感資訊與環境變數（除 `.env.example`）
- `*.log`: 各類日誌檔
- 作業系統或編輯器的快取檔 (`.DS_Store`, `.vscode/`)
