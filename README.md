# 分帳即時通

使用 React、Vite 與 Firebase Realtime Database 製作的多人分帳工具。

## 手機記帳與同步

- 新增、編輯、刪除會先寫入此裝置的待同步清單，再依群組順序上傳。重開 App、恢復連線或回到前景時會自動補傳；雲端更新會與尚未上傳的操作合併。
- 未完成的費用／轉帳草稿依群組及使用者保存在此裝置，重新開啟記帳視窗可繼續填寫。保存記錄後會清除草稿。
- 同步狀態顯示離線、待同步筆數、同步中或已同步。裝置上的草稿與待同步清單不是跨裝置備份；清除網站資料也會清除它們。
- 手機彈窗跟隨可見畫面高度，標題與儲存列固定，中間表單獨立捲動。明細先顯示最近 50 筆，可載入更多；搜尋涵蓋所選期間全部記錄，不受分批載入限制。輸入關鍵字後可切到「全部日期」，跨月份及年份搜尋同一本帳本，沿用分類與成員條件；切回目前日期／期間仍保留原條件。跨月份搜尋時顯示搜尋結果與每筆日期，隱藏原日期摘要，避免誤認成當日支出。
- 手機新增／編輯記錄時，直接在原欄位輸入，鍵盤上方提供下一欄與完成按鈕；完成輸入後使用原本的儲存按鈕。新增費用預設餐飲，分類含旅遊共十三項；舊帳目分類保持相容。常用範本操作已移除。

## 個人與共用帳本

- 個人帳本新增時可切換「支出／收入／儲蓄」。收入以正數記錄；儲蓄是資金移轉，可選存入或轉回，不灌入消費支出或收入。三種類型都支援編輯、刪除復原與離線待同步；未完成的收入／儲蓄草稿保存在本機。
- 個人明細預設「按日看」，可滑動日期列直接看當天記錄與支出小計；「整月看」按日期分組顯示，日期旁列出完整小計，不受分批載入筆數限制。月份選擇、前後月份及「今天」直接顯示；清除篩選會回目前月份、今天，並清空分類與搜尋，不跳到全部歷史。
- 「按日看／整月看」依帳本保存在此裝置。重新開啟仍以今天及目前月份開始，不沿用過去日期或搜尋。明細與統計各自保留捲動位置、已載入的清單及報表選擇；再次點目前分頁可回頂端。刪除帳本時一併清除該帳本瀏覽偏好。
- 在「按日看」新增支出、收入或儲蓄，日期預設為正在瀏覽的那一天；補記與「儲存並繼續」保留日期。新增後切到該筆日期方便確認；編輯既有記錄則保留原本瀏覽位置。
- 個人「統計」保留月報與年報，顯示收入、支出、結餘、每日／每月長條圖、支出分類圓環，以及分類次數與平均，不另設日報。點選分類、圖表日期／月份、收入、儲蓄或付款標籤，會進入獨立統計明細頁，可搜尋與編輯；返回會保留報表期間及捲動位置，不更改一般帳本的日期、分類或搜尋。儲蓄另列，未到期記錄提示且不更改原日期。
- 分類新增「教育學習」「理髮」。ReceiptBox CSV 解析器保留原分類、地點、註記與付款標籤；儲蓄另存，來源編號固定，合法同日同額多筆保留。解析及匯入清單僅在本機處理，使用者的 CSV 與帳目不放進公開網站程式。
- JSON 備份與 CSV 匯出涵蓋收入、儲蓄及來源欄位。收入／儲蓄只允許個人帳本本人存取，銀行背景服務不能讀寫這兩類資料。

- 首頁選「新增帳本」，可建立個人帳本或共用帳本，預設為適合日常支出的個人帳本。既有帳本仍以共用帳本運作。
- 個人帳本自動由自己付款並記為自己的支出，隱藏付款人、分攤、還款轉帳與成員管理。預設顯示本月今天的明細與支出，可切換整月收支、月份與分類；重新開啟 App 會回到上次使用的帳本。
- 個人帳本在資料庫只允許建立者的帳號身分讀寫，不提供邀請碼加入，也不能在建立後直接變更帳本類型。共用帳本保留六位邀請碼、共同記帳與分攤結算。
- 未開啟帳本同步時，個人帳本使用原本的匿名裝置身分，請保留網站資料。開啟同步後可在其他 Safari 或裝置登入同一帳號；JSON 備份仍不包含登入憑證，建議定期匯出備份。
- 個人帳本首頁有「銀行設定」，帳本設定也有「銀行與卡片設定」直接入口，可在既有帳本設定銀行、卡號末 4 碼與分類。「待確認記帳」集中成一列顯示筆數，點入處理銀行通知及共用分攤，不佔滿每日明細。
- 個人帳本可在帳本設定按「刪除個人帳本」。第二個視窗會顯示帳本名稱與記錄數，需輸入「刪除」才能確認；需要連線並完成待同步資料。確認後刪除雲端帳本及本機帳目、草稿、該帳本銀行規則，其他帳本與裝置登入身分保留。伺服器只留下不可修改的裝置 UID／刪除時間標記，防止舊同步或備份重建原帳本；本機不提供復原操作。

### 我的分攤同步至個人帳本

- 共用明細右側只顯示自己的正數分攤，以紅色標示；純代墊及自訂零元分攤留空。付款人及整筆金額仍可核對。
- 在共用帳本開啟「我的分攤同步」，選擇自己的目標個人帳本及起始日期，預設今天且包含當天；依消費日期判斷，更早的帳不補匯。任何成員建立、且自己有負擔的費用都可送入，還款轉帳不計入支出。設定依 UID 私有存放。
- 分攤先進個人帳本的「待確認記帳」，與銀行通知共用入口，分別顯示來源。待確認不計入支出、統計與 CSV；補好說明、分類後才正式入帳。金額依原分帳計算，需更改時回原分帳調整。
- 固定來源編號及處理標記避免重複；忽略過或已確認後刪除的同筆分攤不會自動重建。確認後保留自己填的說明、分類；來源內容修改可再提出待確認，確認後更新原筆。已確認的歷史由本人管理，不因暫停或更換目標帳本刪除。
- 可在開啟同步時直接更換目標。未確認的新分攤移至新帳本，已確認及忽略的來源排除於新目標；原帳本的手動與已確認紀錄保留。切換時重新讀取舊目標的處理標記，避免另一裝置剛完成確認而產生重複。
- 舊版直接入帳流程暫停，需重新指定日期與目標。可勾選「整理舊版同步副本」：起始日期以前的自動副本移除，之後的自動副本改送待確認；手動及 CSV 匯入不動。清理以來源欄位及固定編號辨識，刪除墓碑保留。資料庫規則拒絕舊版繼續新增未確認副本。
- 同日同額的個人手動記錄只提示核對，不自動合併；可忽略已記過的分攤，或明確選擇不同消費。銀行已先記全額時，可在確認分攤時一併改成自己的分攤金額，原子保留連結及去重資訊。銀行通知也可連結已確認的分攤，避免重複計入全額。
- App 開啟時即時核對，重開或回到前景補核對；不依賴背景網頁執行，也不增加付費服務。JSON 備份包含分攤待確認、處理標記及未上傳的確認操作；銀行背景服務無法存取分攤待確認。

## Safari 與桌面 App 的帳本同步

- 首頁、帳本設定及銀行設定都有「帳本同步」入口。先在原本記帳的 App 選「我是原本記帳的 App」並綁定 Email／密碼，再在 Safari 選「我已設定，要登入」。Firebase 的匿名帳號連結保留原 UID，因此既有個人帳本權限不變。
- 帳目沿用原資料庫；帳本清單與銀行設定會同步。草稿及尚未上傳的紀錄仍只在該裝置，清除網站資料前必須先同步完成。
- 若另一個 Safari 身分也已有獨立帳本或待同步紀錄，登入會先阻止換身分，避免原匿名帳本失去存取權；不自動合併兩個帳號。
- iOS 捷徑開啟普通網址時仍可能進入 Safari；本功能透過同一帳號共用資料，不依賴未公開的強制開啟桌面 App 協定。

## iOS 銀行通知捷徑

個人帳本提供背景接收版：Richart 通知經自己的 Cloudflare Workers 免費接收服務驗證銀行與末 4 碼後，先進原本 Firebase 的「手機通知待確認」，成功時不開 Safari。待確認不計入支出、分類統計或 CSV，補好說明與分類後才正式入帳；不串接 AI。

銀行通知與共用分攤各自提供連續確認，顯示本次進度及「確認並下一筆」，也可確認後返回清單。每筆使用各自的說明、分類與草稿；未填妥時不前進，返回清單保留輸入。開始後的新通知留待下一輪，選下一筆時會略過已由其他裝置處理的項目；仍需逐筆核對可能重複的帳目。

接收服務使用 Cloudflare Workers Free，帳本保留 Firebase Spark，不需要 Blaze、信用卡或付費綁定。免費額度用完會拒絕請求，不自動升級。部署順序、受限服務身分與測試方式見 [worker/README.md](worker/README.md)。

在原本桌面 App 開啟「銀行自動記帳設定」，或前往 [手機三步安裝頁](https://jameschen9801.github.io/Expense-Splitting/#bank-install)。一次只顯示目前步驟，只安裝「銀行背景記帳」及「Richart 背景記帳」兩個捷徑。

進度保存在這台裝置，依同步身分、帳本及主捷徑版本區分。銀行資料由雲端驗證；主捷徑需在本次綁定後，收到目前裝置憑證的新連線測試才打勾，同帳號其他裝置的測試不會誤算。通知自動化開關由使用者在 iPhone 確認，明確標示「你已確認」；真實消費通知的接收結果另行顯示。刪過捷徑時可選「從頭安裝」，不刪帳本或銀行資料。

三步依序為：確認銀行資料、加入主捷徑並測試、開啟 Richart 通知。安裝頁提供以下動作：

1. 開啟帳本同步，儲存銀行關鍵字及卡號末 4 碼。不提供完整卡號，也不需在捷徑重填。
2. 加入 [銀行背景記帳](https://www.icloud.com/shortcuts/8648f008f0e94bcdaf81d487cbc16ae8)，回 App 按「已加入，綁定並測試連線」。設定只交給自己的主捷徑，連線測試不新增帳目。
3. 加入 [Richart 背景記帳](https://www.icloud.com/shortcuts/43a2030779cc4fb188f72c1132773e80)，在 iPhone 開啟其自動化開關。已帶入 Richart 通知來源及背景主捷徑，不需另選 Richart Life。

若裝置仍保留舊「Richart 通知自動化」，需停用舊開關，避免它繼續開 Safari；已刪除全部捷徑的裝置直接照三步重新加入即可。

背景服務不保存原始通知，只保存解析後的待確認資料及接收結果。相同 Richart 通知使用 HMAC 去重，包含已知 Richart／Richart Life 標題變體、舊 ID 及已處理墓碑；交易時間不同仍保留為不同通知。驗證碼、退款、失敗、帳單、外幣及不明金額不自動新增。先只接銀行通知，不另接 LINE 錢包。

主捷徑將受限憑證存於 `Shortcuts/ExpenseSplitting-bank-background.txt`，它只能送入自己的待確認，不能讀帳、刪帳或改設定；可在 App 二次確認後停用全部綁定。公開捷徑及一般 JSON 備份不包含憑證。成功、重複或不符合規則時安靜結束；失敗不代表已保存，無網路不會自動補送。鎖定時執行受 iOS 權限限制，請在解鎖時完成首次授權並用實機通知驗證。

無法開啟 Apple 安裝頁面時，使用 App 的 ZIP 備用檔，在「檔案」解壓後加入，避免直接預覽二進位原始檔而顯示亂碼。新版主捷徑與來源原始內容為 `scripts/ios-bank-background.json`、`scripts/ios-richart-background.json`；由 `scripts/create-background-shortcuts.mjs` 產生。簽署檔及 ZIP 位於 `public/shortcuts/`。

### 舊版與共用帳本

原本 [銀行通知記帳](https://www.icloud.com/shortcuts/1e2ff51948f94e508a80098f7367b2f7) 與 [Richart 通知自動化](https://www.icloud.com/shortcuts/bb42192198bf423183c8361030091878) 繼續保留。這條流程開啟 Safari 後才記帳，使用同一個同步帳號連回原本帳本；通知以網址片段傳入並立即移除，不進 HTTP 查詢參數，不保存或上傳原始通知。最近接收結果僅存該瀏覽器。

個人帳本的舊版通知同樣先進待確認；共用帳本沿用原本測試、同意與分攤規則。原始範本為 `scripts/ios-bank-shortcut.json`、`scripts/ios-richart-trigger.json`。可從個人設定內收合的「舊版：開啟 Safari 記帳」查看；切換時請手動停用舊來源，避免它仍開網頁。

## 🚀 快速開始

### 1. 安裝套件
確保你已經安裝 Node.js，然後執行：
```bash
npm install
npm ci --prefix worker
```

### 2. 啟動開發環境
啟動開發伺服器：
```bash
npm run dev
```

### 3. 執行檢查
```bash
npm run lint
npm run test:logic
npm run build
```

### 4. 建置與部署
本專案已設定 GitHub Actions。當程式碼推送到 `main` 分支時，會自動觸發 `.github/workflows/deploy.yml` 腳本，將 `dist` 的靜態網頁內容自動部署至 GitHub Pages。
- 請確認 GitHub Repository 的 **Settings -> Pages** 中的 **Source** 已設定為 **GitHub Actions**。

### 5. Git 忽略檔案設定
本專案透過 `.gitignore` 已排除：
- `node_modules/`: 第三方依賴套件
- `dist/`, `build/`: 編譯後的輸出檔案
- `.env*`: 敏感資訊與環境變數（除 `.env.example`）
- `*.log`: 各類日誌檔
- 作業系統或編輯器的快取檔 (`.DS_Store`, `.vscode/`)
